# Inactive viewer qualification engineering sources

These are the viewer-owned guard, native admission and diagnostic sources
previously developed only in Origo. Their placement here does not enable a
command, grant an allocation, install a provider or establish a native result.
No package script or automatic test discovery invokes this directory.

`migration-map.json` binds each original file at immutable Origo commit
`b022d0097851c34d7300e7843ac4cbc10b780299` to its exact destination, original
and destination hashes, sizes and literal edits. Origo's original decisions,
reviews and observed evidence remain historical records. Source relocated
here is the starting point for further viewer engineering.

- `compact-guard/` keeps the mutually importing guard, lease adapter,
  coordinator, peer, fixture, acknowledgement checker and result oracle
  together. Its C broker/bootstrap/identity files are reference sources;
  this relocation compiles nothing. The baseline guard remains exact.
- `native-admission/` selects the latest VD14 native caller and owner, with
  the unchanged C source and original provider inventory records. Earlier
  startup-profile callers/owners are superseded history, not parallel active
  implementations. `checks/` holds the startup and membership diagnostic
  sources; `design/controls-data.json` holds the 25 inert declarations.
- `historical-bindings/` directories preserve original seals, inactive
  templates, command descriptions and diffs. Their hashes and absolute paths
  describe the original packets. They are not effective commands for this
  relocated tree. Original `PENDING` labels are preserved as historical text;
  subsequent source review is recorded in the owning study.

## Relocation delta and unresolved closure

Only eight distinct source literal replacements were made, in three files:

1. `compact-guard/run.mjs` resolves the viewer's `tec-os/package.json` through
   `../../../tec-os/package.json` relative to its own module, preserving
   resolution through the pinned submodule's dependencies.
2. The native caller derives `BASE` from its own source directory, uses the
   adjacent C source and reads the adjacent provider file/link inventories.
3. The native owner derives `SOURCE` from its own directory and reads those
   same adjacent provider inventories. Its caller therefore resolves locally.

All JS sibling imports and Python oracle imports retain their original
relative structure. Provider inventories were copied exactly; they describe
historical/prospective Mac paths and do not supply those files. The relocated
guard `source-seal.json` freshly inventories its effective sibling sources and
excludes the old command description, which lives under historical bindings.
It is a source hash inventory, not a runtime qualification seal. No native
allocation/permit is produced; historical native permits bind old bytes and
cannot serve as the new caller/owner's reviewed-input closure.

All files are regular, non-executable mode0644. This portability is of source
location, not platform: Darwin API layouts, pinned Node/Python/clang/ld/SDK,
clock domain, coordinator lock and output paths remain the original explicit
contracts. No Linux substitution, new provider, changed limits, observed
resource cost, SDK capability or supported Mac executor is asserted. The native
source still requires independently reviewed startup/provider/command/input
bindings, registered controls and separate root allocation before any B/R/API
or diagnostic execution. A5 and the native admission prerequisites remain open.

Historical held-state/abort scripts bind past process identities and stay with
their original observations; they are not reusable qualification controls.
Captured results, binaries and archives were not copied into engineering
source. The migration map records these exclusions.
