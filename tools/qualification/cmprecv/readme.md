# Viewer receiving policy model

This packet prepares the 34 M0 host cases admitted for source authoring by
Origo VD-15 at b1af49a9. It changes no production page or firmware pin.
The command is inactive. Independent source review and a published root
allocation must precede execution.

`cases.dat` preserves the original declarations byte for byte. Only its
`hostCases` run here: 17 width/storage cases, ten notice cases and seven
identity cases. The scene and browser declarations remain data. `oracles.dat`
fixes the synthetic text, literal HTML, single mutations and first reason
codes before model authoring. The driver compares results with these separate
oracles. A generic exception cannot satisfy a declared negative case.

The width model applies 32, 40 or 80 columns. Missing, invalid and unavailable
storage start at 40. A failed write leaves the selected session width in use
and preserves the old stored value for reload. These are proposed receiving
semantics, not observations of the current Viewer page.

The notice model checks the exact canonical bytes before serialising text.
Directory output includes a notice copy and inline HTML. Standalone output
contains inline HTML only. The separate escaping fixture contains angle
brackets, an ampersand and quotes. Exact literal HTML and decoded text are
checked without a browser or DOM. The canonical notice has 2642 bytes and no
characters needing this escaping. Its HTML has 2721 bytes. Missing, truncated
and one-byte-changed inputs require NOTICE_MISSING, NOTICE_LENGTH and
NOTICE_HASH respectively. Failed notice cases produce no notice artifact.

The identity model checks ROM, font, a structured dependency descriptor,
app body, recipe body, notice body and PICO version 3. Each control changes
one field. Compound-fault precedence is untested.
VD-16 at c9ca25a0 corrects the dependency subject from the old opaque inventory
mutation. The original ccddacdd source packet is preserved externally.

`deps.dat` binds every file in the complete 628aeb2 Viewer baseline, its fe209
gitlink, the effective M0 source projection and actual host provider files.
It includes the actual Viewer package bytes and records the absent root npm
lockfiles. The delegated TEC-OS package and lock are separate exact copies.
All resolved roots, files and original hashes are explicit. The driver joins
the positive descriptor to actual files before the dependency contrast.
The fixed mutation changes only the declared Node executable row hash.
The installed executable is unchanged. `source/deps.dat` and `depnew.dat`
retain the complete original and altered descriptors. The case reading also
retains both versions of that named row and the positive file-join summary.
Generic descriptor, file or preflight errors cannot count as the semantic
IDENTITY_DEPENDENCY refusal.

The descriptor's source projection excludes only deps.dat, offer.dat and
oracles.dat to avoid their enclosing digest cycle. The offer binds all files
and a later allocation binds the offer. The 175 Viewer baseline files are
joined to every original Git blob in the coordinator's complete tree export.
The new M0 projection is separate from that baseline. Other baseline sources
are provenance context and are not imported by this host model.

The host provider closure contains 1022 actual regular files, its five links,
four absences and closed standard-library set. Builtin imports resolve through
the pinned Node executable and the outer's standard-library closure. No package
resolver or browser dependency is imported. This descriptor does not establish
a canonical browser installation. Playwright/core, browser/driver and later
consumer dependencies still need their own M1+ installed-file proof. The 37
canonical firmware/web artifacts are not a Viewer node_modules inventory.
App, recipe and notice body fixtures remain archived upstream bytes. Their
model results are not HTTP delivery or browser observations.

`inputs.dat` records the complete unchanged 37-artifact archive and all 24
P6 generated-input rows. `inputs/archive.bin` preserves the original compressed
archive. Only the finite active fixtures are copied separately. SAMPLE source
is recovered from the archived 5106-byte delivered file by removing its final
EOF byte and converting CRLF to LF. The result is the original 4874-byte
source with SHA256 916357ae8e71b2264f0dc73f79ba801b44ea408cc39910d27de6dce41daf2d52.
The current TEC-OS SAMPLE source is not substituted. The recovery is DATA work
and provides no card, cursor, generated-symbol or native proof.

The future command runs `launch.py` under isolated Python with a cleared
four-key environment. The outer starts GNU timeout, the unchanged shared
guard and one Node driver. The guard provenance is Origo commit
b7baea901b00fda3f0d26a3796a9f877812c4f43 and blob
947fb8cc89a1fb9ed31e0d21f291cc23c39552d0. The driver checks effective child
denial before importing `model.mjs`. It retains its actual PID, direct guard PPID, argv,
Node flags and complete environment. Filesystem permissions are broad enough
for sealed source and fresh outputs. They are not a filesystem sandbox.

`offer.dat` seals the source rows and provider closure. The offer excludes its
own digest from its member list to avoid a self-reference. A later allocation
binds the actual offer digest. The outer passes that digest as M0_OFFER_SHA.
The driver checks it and archives the offer with all other source files.
The resulting environment also contains the guard's ORIGO_GUARD and exact
NODE_OPTIONS heap64 setting. Neither old C5 measurements nor any previous
Viewer proof counts as this command's memory or timing result.

Normal retention consists of every sealed source copy, 34 individual case
readings, six notice files, the altered dependency descriptor and four aggregate
files. `files.dat` inventories every other output. The driver creates exclusive
mode 0600 files in private 0700 directories using public Linux O_SYNC flags.
A checked full-write loop requires positive progress and closes every owned FD.
All 26 staged source files are nonempty with a smallest source of 441 bytes.
JSON records include their final LF. Notice outputs have 24, 113, 2642 or 2721
bytes. The positive-length check preserves every declared write path.
The maintained packet is mode 0644. A first
failure retains completed readings and a bounded failure record when the
output directory exists. The failure record names the active case and phase,
including positive setup and file joins. Earlier setup failures remain in raw
captures. There is no retry, warm-up, sweep or automatic allocation.

The original 44 Viewer tests, VS3/VS4 browser work, Mac B/R/700 MiB requirements
and A5 native positive/failing pair remain unchanged and unresolved by M0.
No D or B lifecycle proof, native success, browser pass, production witness
or gate acceptance follows from this packet.

The source03 writer replaces the permission-mode fsyncSync operation identified
by VM0-02. It uses public fs.constants and writeSync under the same child-denied
permission flags. No internal API or permission bypass is used. No M0 actual
has established this successor's compatibility, time, price or semantics.
After the actual writer wait, the Python outer fsyncs and reads each finite
complete or partial evidence file through EOF, checks its stable identity and
fsyncs the validated private directories. This precedes outer SELF. Raw capture
FDs are set to 0600 before Popen. The guard log and final outer receipt are also
0600. A failed or incomplete audit prevents normal acceptance and root retains
the full actual tree and captures, including files absent from an inventory.
The final outer receipt is fsynced through its owned FD in the bounded tail.
Its parent directory is not covered by the worker evidence-directory audit.
No physical-media or power-loss guarantee follows from these file operations.
